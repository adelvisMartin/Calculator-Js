# InSave v0.18 QA Matrix

## Automated quality pipeline
The v0.18 quality workflow is intentionally broader than `assemble`.

### Source/reconstruction
- pinned YTDLnis source;
- v0.17.2 LKG reconstruction contracts;
- v0.18 security/build hardening;
- v0.18 identity;
- v0.18 instrumentation suite installation.

### JVM/static gates
- `testGithubDebugUnitTest`;
- `lintGithubDebug`;
- debug/release/Play/test APK compilation;
- critical-warning ratchet;
- security/privacy gate;
- resolved dependency graph;
- CycloneDX SBOM.

### Packaging gates
Universal Heavy QA APK must pass ZIP integrity and include:
- arm64-v8a;
- armeabi-v7a;
- x86;
- x86_64;
- `libpython.so`;
- `libffmpeg.so`;
- `libffprobe.so`;
- `libaria2c.so`;
- `libqjs.so`.

The artifact receives SHA-256 and is never described as production-signed unless an actual production release key is supplied through CI secrets.

### Play policy gate
CI compiles `playDebug`, inspects the **merged manifest** and blocks if it contains:
- `MANAGE_EXTERNAL_STORAGE`;
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`;
- `SCHEDULE_EXACT_ALARM`.

`INTERNET` remains expected.

### Android API 35 runtime gates
The emulator must run with KVM acceleration. Tests create fourteen WhatsApp fixtures plus a WhatsApp Business fixture and prove:
- automatic WhatsApp discovery;
- automatic Business discovery;
- at least fourteen fixture records;
- late item `insave-auto-test-12.jpg` exists;
- Provider B primary request uses `mweb` + fresh per-video PO token;
- `web_embedded` and `android_vr` fallbacks are explicit and do not reuse mweb PO material;
- candidate-pool Provider B produces a real MP3;
- two selected jobs produce two distinct real MP3 files;
- Provider C is off by default;
- private cleartext Provider C endpoint is rejected.

### Visual/device-state automation
The same emulator captures nine screens and XML dumps:
1. Inicio;
2. Estados WhatsApp top;
3. Estados after RecyclerView scroll;
4. late-status search;
5. WhatsApp Business;
6. Descargas;
7. Seguidores;
8. Ajustes;
9. Back to Inicio.

The gate compares visible status item sets before/after swipe; a screenshot alone does not prove scrolling. It also records PID before/after Back and requires the process to remain alive.

### Runtime privacy gate
Android logcat is retained. CI blocks obvious PO/visitor token value leakage.

## Public-video candidate-pool policy
A single public YouTube test video is not sufficient in 2026 because challenge treatment can differ by video/session/runner. v0.18 keeps a small long-lived public candidate pool and requires real outputs:
- at least one Provider B public candidate must produce a real MP3;
- two different selected jobs must each produce a distinct real MP3.

This does not lower the product requirement: real conversion remains mandatory. It only prevents one temporarily challenged test asset from being misclassified as a whole-app regression.

## Physical-phone Stable checklist
Run against the exact SHA-256 artifact that passed automation.

### Install/start
- fresh install succeeds;
- update over previous Recovery succeeds if expected;
- first launch does not crash;
- launcher icon/name correct;
- no technical package-update modal blocks normal use.

### Home/search/download
- search a song/artist by text;
- paste public YouTube URL;
- MP3 remains primary;
- 320/256/192 kbps selector behavior matches UI;
- public anonymous download does not request YouTube login/cookies;
- completed MP3 opens in a compatible media player;
- failure message remains understandable when a public URL is genuinely unavailable.

### Playlist/batch
- selection checkbox works for first item;
- selection survives scroll;
- select/invert/clear work;
- selected count correct;
- two or more selected entries create independent jobs;
- one failure does not cancel unrelated jobs.

### Estados
- open statuses without defaulting to a file picker on sideload Recovery;
- more than six real statuses remain reachable;
- search late status;
- image/video filter and counts correct;
- switch WhatsApp/Business;
- save/preview one image and one video;
- return to app without process death.

### Navigation
- every bottom destination works;
- Back from Ajustes/other subview returns to Inicio as designed;
- process remains alive;
- repeated open/back does not create duplicate shell stacks.

### OEM/storage/background
On Xiaomi/MIUI device:
- All Files Access presentation is understandable for sideload Recovery;
- background download survives normal screen-off/use;
- notifications behave correctly;
- status scan refreshes after returning from WhatsApp;
- saved media appears in expected destination.

## Release decision
- Automated green only: **QA Candidate**.
- Automated green + canonical direct build: **Stable Candidate**.
- Same artifact + physical-phone checklist: **Stable**.

Any failed critical item returns the build to Development regardless of numerical score.
